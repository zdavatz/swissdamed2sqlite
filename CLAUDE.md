# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Single-binary Rust CLI that downloads swissdamed UDI (Unique Device Identification) data, actors, and mandates from `swissdamed.ch` and exports as CSV and/or SQLite. Output files are date-stamped and organized into `csv/` and `db/` subdirectories (e.g., `csv/swissdamed_25.02.2026.csv`, `db/actors_25.02.2026.db`). Exception: the MiGeL match DB is written to a fixed `db/swissdamed_migel.db` (overwritten each run, not one file per day); `output_db_fixed()` in `src/export.rs` builds the non-dated path and `migel_stats::find_latest_dbs` recognizes both the fixed name and legacy dated `swissdamed_migel_*.db` files.

## Configuration

Sensitive defaults (scp target, Google Drive credentials) are stored in `config.toml`, which is gitignored. Before building for the first time, copy the sample:

```bash
cp config.sample.toml config.toml
# then edit config.toml and fill in real values
```

CLI arguments always override `config.toml`. If a required value is missing from both, the app shows an error dialog and exits. `config.sample.toml` is committed and contains empty-string placeholders; `config.toml` is gitignored and holds real credentials. The release and CI workflows copy `config.sample.toml → config.toml` automatically before building.

**Credential files live in `~/.config/swissdamed2sqlite/`** (dir 0700, files 0600): `linkedin_credentials.json`, `linkedin_token.json`, `twitter_credentials.json`, and the Google service-account `.p12` (referenced by `gdrive_key`). They used to sit in the repo directory — the `.p12` was world-readable at 0644 and was NOT gitignored, only untracked, so a `git add -A` would have committed it. `.gitignore` now also covers `*.p12`, `*.pem`, `*-key.json`. See `src/credentials.rs` for the lookup order.

## Build & Run

```bash
cp config.sample.toml config.toml  # first time only
cargo build              # debug build
cargo build --release    # release build
cargo run -- --csv --sqlite          # download and output both formats
cargo run -- --csv                   # CSV only
cargo run -- --sqlite                # SQLite only
cargo run -- -f data.json --sqlite   # load from local JSON instead of downloading
cargo run -- --sqlite --deploy       # build SQLite and scp to remote server
cargo run -- --diff old.csv new.csv  # diff two CSVs, output to diff/ folder
cargo run -- --actors                # download actors (CSV + SQLite)
cargo run -- --mandates              # download mandates (CSV + SQLite)
cargo run -- --actors --mandates     # download both
cargo run -- --ar-mandates           # join AR actors with their mandates
cargo run -- --ch-rep                # CH-REP only companies (only AR/IM, no MF/PR)
cargo run -- --ch-rep-mandates       # CH-REP companies ranked by mandate count
cargo run -- --ch-rep-mandates --ar-only  # AR-only CH-REPs ranked by mandate count
cargo run -- --migel                 # match UDI devices to MiGeL codes
cargo run -- --migel --deploy        # match and deploy to remote server
cargo run -- --migel --linkedin      # match + generate PNG + publish PNG to LinkedIn
cargo run -- --migel --twitter       # match + generate PNG + publish PNG to X / Twitter
cargo run -- --migel --linkedin --twitter  # publish to both
cargo run -- --migel-stats           # re-render stats PNG from latest DBs (no download)
cargo run -- --migel-stats --linkedin  # re-render PNG and publish to LinkedIn
cargo run -- --migel-stats --twitter   # re-render PNG and publish to X / Twitter
cargo run -- --linkedin-delete 'https://www.linkedin.com/feed/update/urn:li:share:123/'  # delete a LinkedIn post (URN or full URL)
cargo run -- --sigvaris-shop         # scrape shop.sigvaris.com → GTIN→MiGeL override DB
cargo run -- --lookup-chrn CHRN-AR-20000807  # find all SRNs for a given CHRN
cargo run -- --company-ranking               # rank companies by product count
cargo run -- --unique-srns                   # export all unique SRNs with manufacturer + mandate holder
cargo run -- --details --details-limit 500   # per-device detail enrichment (POC: 500 devices)
cargo run -- --details --details-limit 0 --details-threads 32  # full detail rebuild (overwrites DB, all ~153k udiDis)
cargo run -- --details-update                 # incremental: fetch only new/changed udiDis, append to latest DB
cargo run -- --migel --skip-details           # --migel runs the incremental details update by default; opt out with --skip-details
cargo run -- --triage                        # classify public vs professional in latest udi_details DB (no download)
cargo run -- --status-pdf                     # render one-page A4 status PDF (+ nomenclature legend w/ links) from latest udi_details DB
cargo run -- --csv --gdrive --gdrive-sub user@domain.com  # upload CSV to Google Drive
cargo run -- --company-ranking --mailto "a@gs1.ch,b@gs1.ch" --mail-subject "Subject" --gdrive-sub user@domain.com  # email CSV
```

`cargo test` runs the golden-set regression test (`migel::tests::golden_set`): ~280 rows in `tests/fixtures/golden_set.tsv` (genuine-match exemplars per company × code family, every verified FP cluster as expected-NONE, the excluded-company list, deliberate never-match exemplars, forced-match pins) evaluated against the pinned MiGeL XLSX in `tests/fixtures/migel.xlsx`. Run it after ANY matcher rule change; if a delta is intended, verify each failing row and regenerate the fixture from a verified run. A second test (`migel_stats::tests::render_worst_case_layout`) smoke-renders the stats PNG with a worst-case layout (more legend entries than palette colors, over-long category names); set `MIGEL_STATS_TEST_PNG=/path/out.png` to inspect its output visually. No linter/formatter configuration — use `cargo fmt` and `cargo clippy`.

## Architecture

Modular Rust binary. `src/main.rs` holds CLI parsing (`Args`), `app_data_dir()`, config loading, error-dialog plumbing, and dispatch into the modules below:

- `src/credentials.rs` — where credential files live. `find(name)` resolves a credential path in the order `$SWISSDAMED_CREDENTIALS_DIR` → `~/.config/swissdamed2sqlite` → cwd → `$HOME`; `dir()` returns the preferred directory, `ensure_dir()` creates it mode 0700, `searched_locations()` feeds "not found" errors so they name the expected place. The cwd/`$HOME` fallbacks are legacy and deliberately last — they keep installs working that share the LinkedIn files with `li_push_rs`. An exported-but-EMPTY `$SWISSDAMED_CREDENTIALS_DIR` must fall through rather than resolve to `""` (that would make every credential path relative to cwd); there is a test pinning this. Resolves paths only — the files stay plaintext, the 0700/0600 permissions are obscurity, not encryption. Consumed by `linkedin.rs` and `twitter.rs`; the `.p12` path comes from `config.toml`'s `gdrive_key` instead.
- `src/data.rs` — JSON → header/row flattening (`collect_headers`, `build_rows`, `collect_flat_headers`, `build_flat_rows`).
- `src/download.rs` — paginated POSTs to the swissdamed.ch API (`download_all_pages*`, `load_json_file`).
- `src/details.rs` — `--details` mode: per-device detail enrichment. The slim list endpoint (`POST /public/udi/basic-udis`) carries no intended-purpose/EMDN/characteristic data; the full regulated attribute set lives behind `GET /public/udi/udi-dis/{udiDiId}/details` where `{udiDiId}` is the nested `udiDis[].id` UUID (NOT the `udiDiCode`/GTIN). Public but behind a load-balancer sticky-session cookie (`sm-cookie-be`): first request `302`+Set-Cookie → same URL → `200`; the shared cookie-store client follows it transparently. Pages the list to collect udiDi refs (`--details-limit N`, 0 = all ~193k; ratio ~7.5 udiDis/basic-UDI), then fetches details in parallel via a rayon pool (`--details-threads`, default 32, `map_init` gives each worker its own client/cookie affinity, 3 retries). API tolerates parallelism well (~188 req/s measured, no 429; full run ~20 min). **Incremental + daily hook:** `--migel` refreshes the details DB by default (opt out `--skip-details`), reusing its own UDI download — `update_details()` carries the latest `udi_details_*.db` forward into today's date-stamped file, then fetches details only for NEW or CHANGED udiDis (change key = `udiDis[].lastModifiedAt`), replaces changed rows and drops delisted ones (only successfully-refetched ids are deleted-then-inserted, so a fetch failure never loses a row). `ensure_schema()` migrates older DBs via `ALTER TABLE ADD COLUMN`, and a one-time SQL backfill fills `lastModifiedAt` from `rawJson` so change-detection covers the whole corpus. New rows are triage-classified inline (via `classify()` in `build_row`); run `--triage` to re-classify all after a rule change. `--details-update` runs the same incremental pass standalone (downloads the list); `--details` still does a full overwrite rebuild. Transient `request error for <uuid>` lines are normal on a big run (88 of 2,923 on 27.08.2026) and self-heal: a failed id is never written, so it stays *new* (or keeps its stale `lastModifiedAt`) and the next `--details-update` refetches exactly those — re-running it right away is the fix, no flag needed. Writes `db/udi_details_DD.MM.YYYY.db` table `udi_details` (35 TEXT cols): identity (+`lastModifiedAt`) + intended-purpose (`emdnCode`/`emdnTerm` = EMDN nomenclature ≈ Zweckbestimmung, ~100% coverage; `additionalDescription`; `eudamedBasicUdiUri`) + MDR/IVD yes/no characteristics (implantable/reusable/sterile/measuringFunction/… ; selfTesting/nearPatientTesting/professionalTesting/companionDiagnostics/reagent/instrument/kit/…) + **`rawJson`** = the complete verbatim detail response (verified deep-equal, lossless catch-all: 104 of 133 key-paths — criticalWarnings, storageHandlingConditions, cmrSubstances, clinicalSizes, packages, ownerInfo AR/MF, modelName, referenceNumber, … — live only here, queryable via SQLite `json_extract`).
- `src/triage.rs` — `--triage` mode + `classify()`: labels each `udi_details` row `intendedUser` ∈ {professional, public, review} + `iuConfidence` {high/medium/low} + `iuReason`. **Decision-support, NOT a compliance determination.** swissdamed exposes no structured intended-user field for MDR (95% of corpus); only IVD carries `selfTesting`/`nearPatientTesting`/`professionalTesting`. Two questions are answered, kept separate by confidence: **intended-user** (who is it *for*) via high/medium `public` — only from a structured IVD self-testing signal, **MiGeL membership** (KLV Art. 20 lay-use), or an explicit lay-use text statement (asymmetric: a false high/medium `public` = selling a professional-only device = breach; a false `professional` = only a lost sale) — and **shop-sellability** (may it be *sold* to the public under MepV, default yes unless restricted) via `public/low` (the `PUBLIC_EMDN_CODES` curated allow-list + the TIER-7 presumptive-consumer sweep). `public/low` is a restriction-not-found presumption, always verify IFU; the high/medium public tiers remain the conservative intended-user signals. `classify(detail, migel_code)` takes the device's matched MiGeL position; `load_migel_matches()` builds the `udiDiCode→migel_code` map from `db/swissdamed_migel.db` (else newest legacy `swissdamed_migel_*.db`; best-effort, empty map if absent). Rule order (first match wins): (1) professional/high = AIMDD ∪ implantable ∪ CLASS_III/D — **but a MiGeL match here is a genuine conflict** (e.g. Omnipod 5: CLASS_III yet a real MiGeL home device) → routed to `review/low` with a "MiGeL-listed … but high-risk — verify" note, never silently public/professional; (2) public/high = IVD selfTesting ∪ risk class IVD_DEVICES_SELF_TESTING; (3) professional/medium = IVD professional/near-patient testing (a structured prof-testing field outranks the MiGeL lean); (4) **public/medium = MiGeL match** → KLV Art. 20 Selbstanwendung (legally-anchored lay-use, outranks the noisy free text below; still a lean, not proof — verify against IFU); (4b) **public/low = curated consumer EMDN leaf codes** `PUBLIC_EMDN_CODES` (`V0807`/`V08030102`/`V0811` = anti-decubitus mattresses/cushions/protectors — Class I, freely sellable, no MepV Abgabe restriction, but NOT in MiGeL so KLV Art. 20 can't reach them; a documented maintainer determination — **specific leaf codes only, never a bare category letter**, so false-public stays near-impossible); (5) medium text phrases (EN/DE/FR/IT prof/lay); (6) professional/low = EMDN professional categories `EMDN_PROFESSIONAL_CATS` = L/K/C/G/H/J/S/B/D/P/**Z**/**A** (surgical/interventional/sterilisation/blood-transfusion/device-disinfectants/implant-prosthetics/healthcare-equipment — exclusion-only, asymmetric-safe; F deliberately excluded — home dialysis). **Z (added 28.08.2026) is the one category that is not single-sided**: EMDN files home respiratory therapy, insulin pumps and glucose meters as "equipment" alongside operating tables and scialytic lamps, so 999 of its 18,425 rows carry a MiGeL match. Those are already safe (TIER 4 outranks TIER 6), but their *unmatched* siblings would be wrongly asserted professional — hence `EMDN_PROFESSIONAL_EXEMPT_CODES`, 16 leaf prefixes (CPAP `Z12030102`, home/portable ventilators, O2 concentrators + gas-pipeline regulators, aerosol/nebulisers, peak-flow spirometers — **not** `Z1215` wholesale, which also holds clinical spirometers and body plethysmographs; blood-sugar monitoring `Z12040115` + insulin microinfusors `Z12040216` — **not** `Z120401` wholesale, which also holds dermatoscopes and Holter systems; pulse oximeters, NIBP gauges, breast pumps, wound-treatment equipment). Every prefix is evidence-derived — a leaf where the corpus actually holds a MiGeL match — and an exempt row is merely handed on to TIER 7, so the list can only ever *withhold* a professional assertion, never manufacture a public one. **A (added 28.08.2026) is the same shape as Z**: EMDN files the whole ostomy / urine-bag / pen-needle business under "administration, withdrawal and collection" right next to hospital IV hardware (652 of 4,003 A rows hold a MiGeL match), so A is likewise category-excluded plus exempted at leaf level — `A10` (ostomy, whole branch, MiGeL 29.01), `A06030301`/`A06030399`/`A0680` (urine bags + leg-bag accessories, MiGeL 15.14/15.15), `A0101010201`/`A0101010202` (pen needles, MiGeL 03.07.09), `A020102` (disposable infusion/irrigation syringes, MiGeL 03.07.10.10) and the three home-enteral-nutrition leaves `A030403`/`A03010302`/`A080101` (a maintainer call — tube feed is reimbursed as Spezialnahrung, so no MiGeL evidence exists, but it is unambiguously patient-run). Note A stays in `EMDN_CONSUMER_LEAN_CATS` **as well**: TIER 6 strips the clinical bulk, and what the exemption lets through to TIER 7 is exactly the consumer business that presumption is for; (7) **presumptive consumer (MepV shop-sellability default)** = survived every professional gate above + low-risk MDR/MDD → public/low "sellable under MepV, no Abgabe restriction found, verify IFU": **CLASS_I broad** (lowest MDR risk; professional Class I = reusable surgical instruments already excluded via EMDN L/K), **CLASS_IIA only for `EMDN_CONSUMER_LEAN_CATS` = M/Y/T/A/N** (dressings/aids/incontinence/ostomy/TENS — IIa carries more genuinely-professional devices, so the rest stay review). This answers *"may it be sold to a consumer"* (MepV default = yes unless restricted), NOT *"who is it intended for"* — a restriction-not-found presumption; the broad Class I sweep does catch a few professional-context items (dental mixing tips, OP-fixation bands) flagged low/verify; else review/low with an `EMDN_PUBLIC_LEAN_CATS` = Y/N (orthoses/TENS) lean note. Measured on 167,894 rows (29.08.2026 corpus, 15,205 MiGeL matches, EMDN Z+A rules active): professional 93,624 (55.8%) · public 59,117 (53 IVD-self-test high + 15,204 MiGeL medium + 43,860 low, 35.2%) · review 15,153 (9.0% — the higher-risk tail: Class IIa non-consumer-EMDN, Class IIb, IVD, SPP). Both category additions behave identically and are worth trusting for that reason: each moved rows into professional/low and **nothing else**, with no tier above TIER 6 touched (public/medium, professional/high and professional/medium bit-identical before and after). Z moved 16,391 rows (9,783 from review/low, 6,608 from public/low); A moved 2,875 (2,776 from public/low, 99 from review/low), both counts predicted exactly in SQL from the tier ordering before the code was written. The largest cluster Z corrects: 1,632 `Z12010701` FIXED SCIALYTIC LAMPS — operating-theatre lights the TIER-7 Class-I sweep had been calling "sellable to consumers" — plus endoscopy instruments (252), multi-parameter monitors (313), ECG/ultrasound/polysomnography accessories. For A: low-pressure extension lines (867), flow regulators (419), infusion pump controllers (89), stopcocks (79), intraoperative suction containers (85), blood-gas syringes (66), contrast-media injector syringes (35), biopsy and venipuncture needles. Risk class & EMDN proven NOT to identify public; free text yields <1% reliable signal (`laien`/`selbstanwendung`/`home use`/… combined hit <100 rows corpus-wide) — MiGeL is the strongest derivable lay-use signal, but MiGeL (a *reimbursement* list) ⊊ sellable-to-consumers: verified the official BAG MiGeL (per 01.01.2026, 884 positions) has ZERO mattress positions, so anti-decubitus/Pflege mattresses (CH: covered via Pflege/Spitex Art. 25a KVG, not MiGeL) can never match and are handled by `PUBLIC_EMDN_CODES` instead. Integrated into `--details`/`--details-update` (`classify()` appends the 3 columns during fetch; MiGeL map loaded once per run, and the `--migel` daily hook writes today's MiGeL DB before `update_details()` so new rows see fresh matches); `--triage` re-classifies an existing DB in place (ADD COLUMN + UPDATE, idempotent, re-parses `rawJson` + re-joins MiGeL so it stays the single source of truth). Every `review` row (and any listed product) must be verified against the manufacturer IFU/Zweckbestimmung + MepV Abgabe rules before use.
- `src/export.rs` — `write_csv` (UTF-8 BOM), `write_sqlite[_table]` (identifier-quoted SQL), `output_csv`/`output_db`/`output_pdf` path helpers.
- `src/status_pdf.rs` — `--status-pdf` mode: one-page A4 status sheet (triage distribution + method + key findings) plus a second **nomenclature legend page** (EMDN/MDR/IVDR/MiGeL/KLV/MepV/… with clickable source links). Pure Rust via `genpdf` (writes through `printpdf`), DejaVu Sans embedded from `assets/fonts/` (single-binary preserved; sheet uses no italics so italic slots reuse upright faces). Reads the live distribution from the newest `udi_details_*.db` (`details::find_latest_db`) and writes `pdf/swissdamed_triage_status_DD.MM.YYYY.pdf` (`export::output_pdf`). **All numbers are pulled dynamically — never hardcode a figure in the prose.** Each distribution share also shows its day-over-day change: `find_prev_db()` locates the DB immediately preceding the latest by the DD.MM.YYYY date in the filename (robust against carry-forward mtimes), `delta_pp()` computes the signed percentage-point delta of the share to two decimals (`±0.00 Pp.` when it rounds to zero, so no bare `−0.00`; two decimals so sub-0.1-Pp. daily moves in a growing corpus stay visible instead of collapsing to zero), and `metric()` renders it as a separate small (7 pt, ≈50 % of the 10 pt value) muted run — deliberately NOT 8 pt, which is the `LINK_FONT_SIZE` sentinel. The "review sank from X to Y" bullet likewise derives both percentages live (`before = review + public/medium + public/low`, `after = review`). genpdf 0.2 has no native hyperlinks, so `add_links()` overlays `Link` annotations via `lopdf` 0.34: the legend URL lines are the ONLY text set at `LINK_FONT_SIZE`=8, so the post-process finds them and maps them in document order to `LEGEND`'s URLs (order = source of truth; count-mismatch warns, non-fatal). No download.
- `src/diff.rs` — `diff_csv_files` (compares two CSVs by `udiDiCode`).
- `src/gdrive.rs` — Google API access via the project service account, both directions. **Write:** JWT-signed Drive upload + Gmail send (RFC 2047 subject encoding). **Read** (`--gdrive-download`, `--gmail-search`, `--gmail-attachments`): pull a partner's spreadsheet out of Drive or find the mail that carried it — these were throwaway Python during the Galaxus GTIN work and live here so a repeat run is a command, not a rebuild. All four share `extract_pem_from_p12` + `get_google_access_token`; reading a Workspace mailbox additionally needs `--gdrive-sub` (domain-wide delegation) because a service account has no mailbox of its own. Gotchas pinned by tests: attachment filenames come from the sender and are sanitised so a `../` cannot escape `--out`; Gmail nests parts arbitrarily deep so the payload tree is walked recursively (top-level-only misses forwarded attachments); the Drive read path is `alt=media` raw bytes, which native Google Docs/Sheets do not have (rejected with an explanation rather than a 400). The HTTP client uses a 900 s timeout — reqwest's default cuts a 19 MB download off mid-body and surfaces only as "error decoding response body". Note `Config::load()` reads `~/swissdamed2sqlite/config.toml` (app data dir), NOT the repo copy.
- `src/migel.rs` — Aho-Corasick MiGeL matching engine (shared with fb2sqlite).
- `src/migel_stats.rs` — pure-Rust stats PNG renderer via `plotters` (`generate`, `find_latest_dbs`, `read_stats`).
- `src/sigvaris_shop.rs` — scrapes `shop.sigvaris.com` Shopify endpoints, derives MiGeL codes per GTIN, persists to `db/sigvaris_shop_DD.MM.YYYY.db`. Exposes `find_latest_db` + `load_overrides` consumed by `run_migel` as a GTIN→MiGeL precedence layer.
- `src/error_report.rs` — SRN validation and XSS-escaped HTML error report.
- `src/linkedin.rs` — LinkedIn Image upload + Posts API. Reads `linkedin_credentials.json` + `linkedin_token.json` via `credentials::find` (see below) — same files as `li_push_rs`. Refreshes the token if a `refresh_token` is present and persists it back. Caption auto-built from the MiGeL DB (matched count, %, distinct codes, companies, top manufacturers, top categories). Optional `SWISSDAMED_CAPTION_EXTRA` env var is prepended to the caption (used for one-off context like daily-additions summaries). Triggered by `--linkedin` on `--migel` and `--migel-stats`; failure is non-fatal (logged, exit 0). `delete_post()` (CLI `--linkedin-delete <urn|url>`) issues a `DELETE /rest/posts/{percent-encoded-urn}` to retract a previously published post; accepts a bare `urn:li:share:…`/`urn:li:ugcPost:…` or a full feed URL (URN extracted via `extract_urn`), runs standalone (no download/render) and is fatal on failure (non-zero exit).
- `src/twitter.rs` — X / Twitter media upload (`/2/media/upload`) + tweet create (`/2/tweets`), OAuth 1.0a-signed (HMAC-SHA1, same shape as gigacrawl). Reads `twitter_credentials.json` via `credentials::find` (see below) with `consumer_key` + `consumer_secret` + user-access `token` + `secret`; falls back to the first profile in `~/.twurlrc`. Caption is a compact (<280-char) summary built from the MiGeL DB; optional `SWISSDAMED_CAPTION_EXTRA` env var is prepended (keep it short — tweet budget after base ~206 chars is roughly 70 chars). Triggered by `--twitter` on `--migel` and `--migel-stats`; failure is non-fatal.
- `src/reports.rs` — high-level workflows: `run_migel`, `run_ch_rep[_mandates]`, `run_ar_mandates`, `run_lookup_chrn`, `run_company_ranking`, `run_unique_srns`.
- `src/gtin_report.rs` — `--gtin-report` mode: joins a partner's GTIN xlsx against swissdamed + MiGeL + the EUDAMED mirror + GS1 Firstbase + GS1 Trustbox and writes one spreadsheet (48 cols, 3 sheets). Field precedence is first-non-empty with swissdamed ahead of EUDAMED (Swiss-market record wins), GS1 catalogues last. swissdamed/MiGeL resolve from the newest local DBs; `--eudamed-db`/`--firstbase-csv`/`--trustbox-xlsx` are optional and a missing one narrows rather than fails the report. **Two bugs this replaced, both pinned by tests:** the Python original guarded Trustbox rows with `len(row) < 14` and silently dropped 24,079 of 96,289 rows (openpyxl returns short tuples when trailing cells are empty) — costing ~1,020 matches; and calamine hands integer-valued cells back as `Data::Float`, so a GTIN naively stringified becomes `7640127798065.0` whose digit-strip appends a zero and never matches (`cell()` renders whole floats as integers). Output deliberately leads with a hits-only sheet and colour-codes partner vs. added columns: a 120k-row list where ~8% match opens on empty rows and reads as "nothing was delivered". Standalone, no download.
- `src/gui.rs` — egui/eframe GUI (background worker, error dialog).

### GUI (`src/gui.rs`)

When launched without arguments, opens a native GUI window (egui/eframe, wgpu rendering). Features:
- **Download Products (CSV + SQLite)** — runs `download_all_pages()` + `write_csv()` + `write_sqlite()` in a background thread
- **Lookup SRNs for CHRN** — text input + button, mirrors `run_lookup_chrn()` logic
- **MiGeL Matching (SQLite)** — downloads UDI + MiGeL XLSX, runs Aho-Corasick matching, saves SQLite
- **Open Output/CSV/DB Folder** — opens `~/swissdamed2sqlite/` subdirectories
- Worker thread with `mpsc` channel for non-blocking UI updates
- Persistent settings saved to `~/swissdamed2sqlite/settings.json`
- Light theme (white background)
- App icon embedded in binary from `assets/icon_256x256.png`
- Version shown only in window title bar (not duplicated inside the window)
- On Windows release builds: `windows_subsystem = "windows"` hides console window; CLI mode re-attaches parent console via `AttachConsole(ATTACH_PARENT_PROCESS)`

### Output Directory

All output files go to `~/swissdamed2sqlite/` (`app_data_dir()`):
- macOS sandbox: container directory
- Windows: `%USERPROFILE%\swissdamed2sqlite\`
- Linux/macOS: `~/swissdamed2sqlite/`
- Subdirectories: `csv/`, `db/`, `diff/`, `html/`, `logs/`

## SRN Validation (src/error_report.rs)

- `is_valid_srn()` validates SRN format: 2-3 letter country code + `-MF-` or `-PR-` + 6+ digits. Tolerates minor variants (underscores, unicode dashes, missing dash before digits). Rejects `-AR-`/`-IM-` role types.
- `InvalidSrn` struct holds invalid SRN with manufacturer and mandate holder context.
- `write_srn_error_report()` generates `html/srn_error_report_HHhMM.dd.mm.yyyy.html` with styled table of invalid entries, deduplicated by SRN.

## Build & Release

The `winit` crate is patched locally (`winit-patched/`) to remove `_CGSSetWindowBackgroundBlurRadius` — a private macOS API that causes App Store rejection. Applied via `[patch.crates-io]` in `Cargo.toml`. Same patch used in eudamed2firstbase/eudamed2swissdamed.

## Key Details

- All SQLite columns are TEXT type; no numeric types used.
- CSV output includes a UTF-8 BOM (`\xEF\xBB\xBF`) for Excel compatibility.
- The API client uses a browser-like User-Agent and cookie jar.
- `rusqlite` uses the `bundled` feature (ships its own SQLite, no system dependency needed).

## MiGeL Matching (src/migel.rs + src/sigvaris_shop.rs)

Two-layer pipeline reaching ~15,200 matches from ~167,900 rows (~9.1%; 29.08.2026 — the ratio keeps falling because the corpus grows far faster than the MiGeL-eligible share of it):

**Layer 1 — GTIN overrides** (`src/sigvaris_shop.rs`): scrapes `shop.sigvaris.com` Shopify endpoints (~432 products, ~18k variants), derives MiGeL codes per GTIN from `option2` (Kompressionsklasse) + `product_type` (Wadenstrumpf/Schenkelstrumpf/Strumpfhose/Maternity/Armkompressionsstrumpf/Flachstrick/Wraps/Anziehhilfe), then persists to `db/sigvaris_shop_DD.MM.YYYY.db` with table `sigvaris_shop_variants(handle, gtin13, gtin14, sku, title, product_type, klasse, migel_code, migel_reason)`. Trigger via `--sigvaris-shop`; takes ~7 min with 1s throttle, retries on 403. In `run_migel`, `find_latest_db` + `load_overrides` build a `HashMap<gtin, Option<MigelCode>>` consulted before the heuristic matcher: `Some(code)` → assign that code, `None` → explicit skip (BAG Kap.17: Stützstrumpf / Anti-Thrombose / Reisestrumpf / Klasse 1 are NOT Pflichtleistung).

The scraper is **resume-capable**: per-product variants are appended to `db/sigvaris_shop_partial.db` (with a `done_handles` checkpoint table) immediately after each successful fetch. Rerunning `--sigvaris-shop` skips already-processed handles. When an individual fetch fails after retries, the scraper falls back to the cached variants for that handle from the previous finalized DB. The master handle list per run is the union of (newly discovered) ∪ (partial done) ∪ (baseline DB handles), so Cloudflare-blocked discovery doesn't drop known products. A final **80 % baseline floor** rejects partial scrapes: if the final variant count is below 80 % of the previous finalized DB, the partial is preserved and a future `--sigvaris-shop` resumes from it (no destruction of the override DB). `find_latest_db` excludes `sigvaris_shop_partial.db` and sorts by date-from-filename (`DD.MM.YYYY` → `YYYYMMDD`) so a manually restored older DB is honoured even if its mtime is fresher than a junk replacement.

**Layer 2 — Heuristic matcher** (shared with fb2sqlite). Adds ~7,300 matches via Aho-Corasick (~6,800 non-SIGVARIS plus ~460 SIGVARIS rows the GTIN layer does not cover). Match order inside `find_best_migel_match`: (1) **FORCED_MATCHES**, (2) **metadata gate**, (3) universal exclusions, (4) Aho-Corasick scoring. Key features:
- **FORCED_MATCHES** (`src/migel.rs`): curated recall pins `(all_of, none_of, position_nr)` checked against the RAW pre-enrichment text — for verified brand/category-exclusive tokens where scoring can't reach the right position (verbose Bezeichnung dilutes the single-keyword score below threshold, e.g. "Krücken für Erwachsene, ergonomischer Griff") or IDF would drift to a sibling. Rules: GCE MediSelect/MediReg→14.10.42 (O2 regulators), gehstuetze→10.01.01 (crutches), contact lens/kontaktlinse→25.01.01, Respironics Trilogy/Garbin/BiPAP-A30/A40→14.12.02 (home ventilators), DreamStation/System One/REMstar/Dorma/BiPAP→14.11.02 (autoSV→14.11.03) with accessory stop-lists (circ/tubing/humidifier/mask/filter/accessor/...), spirobank/spirometer→21.01.15, omnipod→03.02.01, doff→17.12.01.01. Rule order matters (first match wins; "bipap a30/a40" ventilators before bare "bipap"). Forced pins deliberately outrank the metadata gate (Omnipod 5 is CLASS_III yet genuine MiGeL).
- **Metadata hard gate**: `is_metadata_excluded()` — deviceType IVDR/IVDD and riskClass CLASS_III rows (~5.2% of corpus) never reach the heuristic matcher, immunizing them against keyword drift.
- **Aho-Corasick** automaton for single-pass candidate finding
- **IDF-weighted ranking** (capped at 5.0) for choosing the best MiGeL code; ties broken deterministically by position_nr (candidates come from a HashSet — without the tiebreak, sibling positions like Kauf/Miete variants flipped randomly between runs, producing phantom daily diffs)
- **English-to-German enrichment**: ~85 medical terms translated (e.g., "knee" → "knie knieorthese", "nebulizer" → "vernebler aerosol", "petrolatum" → "impraegnierte wundkompresse"); context-aware: "ortho" + "rehab" → "spezialschuhe". Region-gated recall blocks: compression `garment`→Leib/Rumpf 05.11 (body) / 17.15.01 (leg) / 17.15.03 (arm) / 17.15.05 (face/head/neck/ear) via "<region> garment" **bigrams** with precedence leg > arm > face > ear (bare region words mis-route: Macom's deviceName "Leg, Arm and Ear Garments" feeds all three words to every row); `ostomy`/`stomabandage`→Stoma-/Fistelversorgung 29.01; `urine`+`bag` / `leg bag`→Bein-/Bettbeutel 15.14/15.15 incl. accessory positions (Beinbeuteltasche/Haltebänder/Halterung); `superabsorbent`/`gelling`→35.05.05/.07; `Halskrawatte`→Cervikalstütze; `Gilchrist`→Schultergürtel-Orthese 22.09; pen+needle→Penkanülen 03.07.09; insulin+syringe→03.07.10.10; incontinence/inkontinenz-compounds→15.01; CGM gate (glucose+monitoring+continuous|flash)→Sensoren 21.07.02 / Lesegerät 21.07.01; breast+pump→Milchpumpen 01.01; ketone strips→21.03.01.03; armtraggurt / arm+sling→Armtraggurten 05.10; cast/post-op/offloading shoe→Spezialschuhe für Verbände 26.01.04.02/.03.
- **Category hierarchy keywords** from MiGeL XLSX parent categories
- **Per-language scoring**: DE (suffix + fuzzy >= 6 chars + compound decomposition), FR/IT (exact word only). `COMPOUND_PREFIXES` includes body-part prefixes (knie/ellenbogen/sprunggelenk/unterschenkel/finger/inkontinenz) so German one-word compounds like `Knieschiene`→`knie`+`schiene` match the body-part keyword.
- **Precision filters**: stop words (incl. generic FR company tokens `fabrication`/`medicaux`/`produits`/`conception` that otherwise leak in via the appended company name), universal exclusions (PTA/stent/ERCP/surgical gloves, AGFA imaging, CSF/ventricular catheters, staining reagents, traction devices, full-body garments, hot/cold compresses — lift that one if a ch.16 recall rule is ever added), ~75 negative keywords per MiGeL code prefix incl. chapter-wide rules (catheters / blood-pressure monitors / coils / arrays ∉ orthosis chapters 22/23), company exclusions.
- **Thresholds**: 2+ keywords: score >= 0.3, max len >= 6; single keyword: score >= 0.5, len >= 8 (>= 0.7 for verbose)
